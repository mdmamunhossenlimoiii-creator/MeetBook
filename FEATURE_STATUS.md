This document records repository source status and CI evidence only. Passing CI does not prove that owner-only Firebase/Cloudflare setup, live staging integration, or production deployment has been completed.

| Profiles and privacy | Full `publicProfiles/{uid}` metadata is restricted by Firestore Rules to the owner, staff and bots; it is visible to everyone when `profileVisibility == everyone`, or to friends when `profileVisibility == friends`. A separate `publicDirectory/{uid}` exposes only display name/name search and minimal account markers for discovery; it excludes bio, photo, cover and settings. | Global/Friends search uses the minimal directory. A private profile route shows only the directory name and friend-request controls when detailed metadata is denied. Profile visibility and directory projections are bound to canonical `users/{uid}` fields using `getAfter`. Public posts remain governed by each post's own audience and may still appear in feeds. The safe admin backfill creates/updates only the minimal `publicDirectory` projection and missing bot profiles. Human detailed `publicProfiles` and `botEngagement` consent projections remain owner-created on the next successful sign-in. Sign-in and owner profile/settings writes replace exact allowlisted projection documents to remove stale legacy fields. The Runner can get one target user's minimal `botEngagement` projection but cannot list the collection; this is a per-document access boundary, not an anonymity guarantee for a UID already known to an authorized Runner. Full existing-account migration verification is still required before release. |

| Bot identities and behavior | 23 built-in fictional bot profiles have role-specific emoji markers; UI keeps the AI Bot disclosure. The first three bots (`bot_01`–`bot_03`) use Gemini with template fallback and up to six recent messages as short-term context. An opt-in, per-user/per-bot long-term memory summary is implemented for those three bots only; raw transcripts are not stored. Missing or permission-denied optional memory documents are skipped without aborting a chat reply. Remaining bots use keyword/template behavior and do not yet have Gemini memory summarization. | Memory is off by default. Users can opt in, see the disclosure, inspect/delete individual summaries, clear all saved summaries, or disable memory. Account deletion also purges owned bot memories. Summaries are bounded to 1,200 characters, built only from user-authored messages, and obvious email/phone patterns are redacted. Real Gemini API memory summarization has not been verified. |
| Bot Runner security | Runner is restricted by an explicit 23-ID bot allowlist and global kill switch; user consent, public-post, private-chat, AI-label, blocked/suspended-account gates for public engagement, private chat history, replies and memory are enforced in Rules. Version-2 inbox items store routing metadata and a message ID only; the sender can get their own metadata and the assigned active Runner can list only version-2 metadata. Runner consent checks use direct per-user gets; Firestore Rules deny collection enumeration. Legacy unversioned items are excluded from Runner queries. The Runner fetches the actual message only after private-chat eligibility passes; staff cannot read inbox metadata or private chat bodies. Admins may create/delete bots and toggle only the `active` Boolean; Firestore Rules deny Admin identity edits, publishing and commenting. | Durable Firestore transaction-backed quotas are implemented and covered by CI/emulator tests: 12 actions per bot per rolling 24 hours; 15 replies per user per bot per rolling 24 hours with a 60-second cooldown; and 20 user-to-bot inbox messages per rolling 24 hours with a 10-second cooldown. Isolated live staging verification is still required. |

## Release decision

**Not release-ready yet.** Current-branch CI is green, but owner-only release gates remain: verify existing-account projection migration; confirm Firebase project/Auth providers/authorized domains and decide on App Check; separately publish the PR #16 Firestore Rules only after an approved merge; deploy the Cloudflare image-upload Worker, set its endpoint and secrets, configure rate/abuse controls, and verify a real upload; and run isolated staging end-to-end checks for a real Runner chat reply, consent-gated public engagement, and Gemini behavior. GitHub Pages/public URL behavior also remains unverified. No credentials or secrets are requested or added here. Do not merge, publish, activate bots, enable unattended workflows, or deploy without separate owner approval.
